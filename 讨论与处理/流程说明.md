# 讨论与处理 · 流程说明

> 本目录与「正式模块资料」严格分离：**讨论、推演、争议、未定方案只在此处**，
> 确认后才**回写**对应模块，绝不反向污染正式资料。

---

## 一、固定流程（每次发现问题的标准动作）

```
① 发现问题
      ↓
② 进入 讨论与处理/
      ↓
③ 建立专题文件夹（命名见 §二）
      ↓
④ 推演（用 _模板/专题模板.md 记录选项/利弊/风险）
      ↓
⑤ 确认（形成结论 + 回写目标）
      ↓
⑥ 回写对应模块（总纲 / 子文件）
      ↓
⑦ 更新模块状态（ STATUS.md + 该模块总纲 §三）
```

## 二、目录与命名约定

- 每个专题一个**独立文件夹**：`讨论与处理/YYYYMMDD-专题简称/`
  - 例：`讨论与处理/20260819-pdf-excel-排期/`
- 专题内必含：`专题.md`（基于 `_模板/专题模板.md` 复制填写）。
- 推演过程、草稿、被否决方案都留在专题文件夹，**不进** `模块/`、`工程总纲.md` 等正式资料。

## 三、与正式资料的边界

| 允许在 讨论与处理/ | 只允许在 模块/ 与导航文件 |
|-------------------|--------------------------|
| 未定方案、备选路径、利弊权衡 | 已确认的目的 / 状态 / 关系 |
| 争议记录、待决问题 | 已落定的子文件清单 |
| 推演草稿、被否决思路 | 实现细节与结论 |
| 临时数据、试验产物 | 完成度与状态数字 |

> 规则：只有**结论**回到正式资料；**过程**留在讨论区。这样正式文档永远干净、可对外。

## 四、回写规范

- 回写前先在专题内写清「回写目标」：具体文件 + 章节 + 改动要点。
- 回写后，在专题 `专题.md` 标记 `状态：已回写（YYYY-MM-DD）`，并在对应模块总纲 §三 更新状态。
- 若回写引发新争议，新建专题，不在一个专题里无限纠缠。

## 五、何时新建专题（而非直接改代码/文档）

- 涉及模块划分调整、范围变更、重大架构取舍。
- 多方案待选、需权衡风险/成本。
- 用户明确说「先讨论」「推演一下」「评估方案」。

小修小补（错别字、状态同步）可不走专题，直接改对应模块总纲。
