# 🎯 UX Test Playbook

> **UX Experience Tester 的操作手册**。每轮测试都按这份清单跑，确保不遗漏。
> Skill Evolver 会根据实际测试反馈自动补齐和进化细节。

---

## 📋 Part 1: 常见 UX 反模式清单

遇到这些 → **必须修**。按危害程度排序。

### 🔴 P0 阻断级

| # | 反模式 | 用户感受 | 检查方法 | 常见位置 |
|---|--------|---------|---------|---------|
| 1 | **操作后无反馈** | "我点了吗？到底生效没？" | 点按钮后 1 秒内看有没有 toast / loading / 状态变化 | AI 处理、网络请求、保存 |
| 2 | **破坏性操作无确认** | "完了，我不小心点了删除" | 删文档/覆盖保存/清空时看有没有确认对话框 | 删除按钮、AI 批量操作 |
| 3 | **错误信息说人话看不懂** | "Unknown error occurred" | 触发错误后看提示有没有说"哪一行/哪个文件/怎么修" | AI 云端调用、PDF 解析 |
| 4 | **加载中白屏无进度** | "卡死了？" | 打开大文档、AI 处理 5s+ 时看有没有 loading 指示 | 大 PDF、云端 AI |
| 5 | **切模块状态残留** | "Mindmap 的残影怎么跑到 Writer 里了" | 快速切 3 个模块后观察有没有 UI 残影 | Canvas 模块（Mindmap/PDF） |

### 🟡 P1 恼人级

| # | 反模式 | 用户感受 | 检查方法 | 常见位置 |
|---|--------|---------|---------|---------|
| 6 | **快捷键不兼容** | "Ctrl+B 怎么不是加粗？" | 拿 Word 的 Ctrl+B/I/U/S 对照测 | Writer、Spreadsheet |
| 7 | **Tooltip 缺失或不清晰** | "这个按钮干嘛的？" | Hover 工具栏按钮看有没有 tooltip + 快捷键 | AI 面板按钮、格式刷 |
| 8 | **按钮 disabled 但没说为什么** | "为什么这个按钮灰的？" | 在不该用的场景下看按钮状态，有没有 hint | AI 替换没选区时 |
| 9 | **确认对话框疲劳轰炸** | "又要我确认？" | 关键操作前弹一次 OK，每步都弹就坏了 | AI 批量润色前问"确定？" |
| 10 | **空状态没引导** | "打开一个空 Sheet 我不知道干嘛" | 新建空白文档时看有没有引导文案 | 新建空白 Mindmap |
| 11 | **拖拽无指示** | "能拖吗？往哪拖？" | 把幻灯片/标签页拖一下看有没有 drop zone 高亮 | Presentation 幻灯片重排 |
| 12 | **保存后不自动关闭** | "存完了，怎么还停在这？" | 存完模板/导出后看状态 | 另存为、PDF 导出 |

### 🟢 P2 可接受但可优化

| # | 反模式 | 用户感受 | 优化方向 |
|---|--------|---------|---------|
| 13 | **Tab 顺序混乱** | "Tab 怎么跳到外面去了" | `tabindex` 检查 |
| 14 | **焦点环不明显** | "我不知道光标在哪" | 加 `:focus-visible` 样式 |
| 15 | **色彩对比度不够** | "浅色字在浅色背景上看不清" | 用 WebAIM Contrast Checker 测 |
| 16 | **窗口极小布局崩坏** | "缩到最小就没法用了" | min-width: 800px 硬约束 |
| 17 | **动画过慢** | "切个模块还要等 500ms" | 过渡动画 ≤ 200ms |
| 18 | **无键盘快捷键** | "AI 润色还要用鼠标点" | 每个高频操作都要有 Ctrl/Cmd+X 快捷键 |

## 🚀 Part 2: 一键化机会识别规则

### 核心原则：**用户要做 N 步才能完成 X，能不能缩到 1 步？**

### 识别 checklist（逐项扫全应用）

| # | 场景特征 | 一键化机会 | 实现模式 |
|---|---------|-----------|---------|
| 1 | 用户**每次**做某件事都选同个选项 | 默认选中 | "保存"默认存原位置、"导出 PDF"默认 A4 |
| 2 | 操作序列 = A → B → C（串行、无分支） | 合并成一个按钮 | "打开 PDF → 选文字 → AI 润色" → **选中即弹建议** |
| 3 | 用户需要在 2+ 个面板间跳 | 面板合并或自动弹出 | 选 Sheet 单元格时自动弹出公式建议 |
| 4 | 同一个快捷键能做多件事 | 智能上下文 | Ctrl+Enter 在 Writer 是"下一段"，在 Sheet 是"确认公式" |
| 5 | 用户**必须**手动填写已知信息 | 自动填入 | 新建文档时自动用当前日期做文件名 |
| 6 | 操作有"预览 → 确认"两步 | 改为实时预览、一键确认 | AI 润色后实时显示 diff，用户一看"好就存、不好撤销" |
| 7 | 对话框多到烦 | 减少 modal，改用 inline toast | 删除操作用 toast +"撤销"按钮替代 confirm dialog |

### 一键化机会发现方法论

```
1. 观察用户（或自己）完成一个任务需要几步
2. 画用户旅程：[起点] → A → B → C → D → [终点]
3. 找可合并的相邻步骤：B→C 能不能合并？
4. 找可跳过的步骤：C 是不是其实是默认值？
5. 输出建议：
   ｜ 当前 N 步 ｜ 目标 1 步 ｜ 实现方案 ｜ 影响面 ｜ 风险 ｜
```

### 一键化机会实现模式库

| 模式 | 说明 | 例子 |
|------|------|------|
| **智能默认** | 记住用户上次的选择 | "导出"默认存上次的目录 + 上次的格式 |
| **选中即弹** | 选中文字 → 自动弹出 AI 建议气泡 | Writer/Sheet/PDF 选区 → selbar 自动浮出 |
| **回车确认** | 输入框里直接按 Enter 触发主要操作 | AI 生成面板 textarea 回车 = 生成 |
| **自动填充** | 已知信息自动填 | 新建文档自动用日期命名、导出路径 = 当前文档所在目录 |
| **实时预览** | 改的同时显示效果 | AI 润色 → 实时 diff 显示 |
| **Inline 操作** | 在当前位置完成，不弹 modal | Sheet 单元格内直接输公式 |
| **快捷键智能** | 同一快捷键在不同上下文做不同事 | Ctrl+S → Writer: save / Sheet: save / AI: submit |

## 📐 Part 4: Nielsen 可用性启发式原则（完整版）

### 原则 1：系统状态可见性
> **用户操作后，系统必须在 1 秒内给出反馈**。用户不该猜测"我点了吗？"、"保存了吗？"、"AI 在处理吗？"

| 检查项 | 达标 | 不达标 |
|--------|------|--------|
| 点按钮后有视觉变化（hover→active→disabled） | ✅ | ❌ |
| 保存操作有 toast 反馈（"已保存"） | ✅ | ❌ |
| 异步操作（AI/网络）有 loading spinner | ✅ | ❌ |
| 长操作（>3s）有进度条 | ✅ | ❌ |
| 出错时有 toast + console.error | ✅ | ❌ 静默吞错 |

**修复模板**：
```js
// ❌ 之前
try { OS.store.put(doc); } catch (e) {}

// ✅ 之后
try {
  await OS.store.put(doc);
  OS.toast("已保存", "ok");
} catch (e) {
  console.error("[save] 失败:", e);
  OS.toast("保存失败：" + e.message, "err");
}
```

---

### 原则 2：系统与现实匹配
> **界面元素应该是用户能认出来的东西**。"保存"按钮图标用 3.5 寸软盘（虽然年轻人没见过，但比抽象几何图形强）。

| 检查项 | 达标 | 不达标 |
|--------|------|--------|
| 按钮文案用动词（"保存"、"删除"、"生成"） | ✅ | ❌ "commit"、"execute" |
| 图标语义明确（垃圾桶=删除、磁盘=保存） | ✅ | ❌ 自造图标 |
| 对话语气口语化（"你确定要删除吗？"） | ✅ | ❌ "confirm operation" |

---

### 原则 3：用户控制与自由
> **用户做错了事必须能撤销**。每个破坏性操作都要有 Cmd+Z 或显式的 undo 入口。

| 检查项 | 达标 | 不达标 |
|--------|------|--------|
| 文本编辑支持 Cmd+Z / Cmd+Y | ✅ | ❌ |
| 删除后有"撤销 toast"（5 秒内） | ✅ | ❌ |
| AI 生成后能一键恢复原文 | ✅ | ❌ 没快照 |
| 关闭对话框 = 取消（不执行） | ✅ | ❌ 关了也执行 |

---

### 原则 4：一致性与标准
> **用户用过的软件教他们怎么操作你的**。Word 的 Ctrl+B 是加粗，我们也应该是。

| 检查项 | 达标 | 不达标 |
|--------|------|--------|
| Ctrl+B 加粗 / Ctrl+I 斜体 / Ctrl+U 下划线 | ✅ | ❌ |
| Ctrl+S 保存 / Ctrl+N 新建 / Ctrl+O 打开 | ✅ | ❌ |
| Delete 键删除选中元素 | ✅ | ❌ |
| Tab 导航顺序符合视觉顺序 | ✅ | ❌ |
| 颜色语义统一（绿=成功、红=错误、蓝=主操作） | ✅ | ❌ |

---

### 原则 5：错误预防
> **好的错误信息不如不让错误发生**。在用户操作前就拦住常见错误。

| 检查项 | 达标 | 不达标 |
|--------|------|--------|
| 删除前有确认对话框 | ✅ | ❌ 直接删 |
| AI 批量润色前有预览 | ✅ | ❌ 直接改 |
| 公式输入时实时语法检查 | ✅ | ❌ |
| 离开未保存文档时提醒 | ✅ | ❌ 直接丢 |

**反模式**：每个小操作都弹确认（疲劳轰炸）。判断标准：**用户误操作的后果严重吗？** → 严重才弹。

---

### 原则 6：识别而非回忆
> **把信息展示出来，让用户"识别"而不是"回忆"**。工具栏按钮 hover 有 tooltip，用户就不用记快捷键了。

| 检查项 | 达标 | 不达标 |
|--------|------|--------|
| 所有工具栏按钮 hover 显示 tooltip | ✅ | ❌ |
| Tooltip 包含快捷键（"加粗 ⌘B"） | ✅ | ❌ |
| 关闭的功能按钮有 hint（"先选文字才能润色"） | ✅ | ❌ 灰掉不说为什么 |
| 常用功能在明面上（不用二级菜单） | ✅ | ❌ 埋太深 |

---

### 原则 7：灵活与高效
> **新手有可视化按钮，老手有快捷键**。两种路径并存，互不干扰。

| 检查项 | 达标 | 不达标 |
|--------|------|--------|
| 每个高频功能都有快捷键 | ✅ | ❌ |
| 拖拽操作同时能用菜单完成 | ✅ | ❌ |
| AI 操作有"自动模式"（一键）和"手动模式"（逐步） | ✅ | ❌ 只有一种 |

---

### 原则 8：美学与极简
> **界面上没有无关信息**。每像素都在为核心任务服务。

| 检查项 | 达标 | 不达标 |
|--------|------|--------|
| 没有装饰性元素（不承载信息的 div） | ✅ | ❌ |
| 留白恰到好处（不挤也不散） | ✅ | 🟡 |
| 配色方案 ≤ 5 种主色 | ✅ | ❌ 彩虹色 |
| 字体层级清晰（H1>H2>H3>body>caption） | ✅ | 🟡 |

---

### 原则 9：帮助用户识别/恢复错误
> **错误信息说人话，告诉用户怎么修**。

| ❌ 坏例子 | ✅ 好例子 |
|----------|----------|
| "Unknown error" | "AI 云端连接失败，请检查网络或切换到本地模式" |
| "Parse error at line 3" | "公式第 3 行语法错误，可能是括号不匹配" |
| "Failed to save" | "保存失败：磁盘空间不足（剩余 12MB）" |
| "Object not found" | "找不到文件 'xxx.pdf'，它可能已被移动或删除" |

---

### 原则 10：帮助与文档
> **用户卡住时有地方看帮助**。但好的界面设计让大部分用户不需要看帮助。

| 检查项 | 达标 | 不达标 |
|--------|------|--------|
| 首次打开有简短引导（30 秒内可跳过） | ✅ | ❌ 什么都没有 |
| 关键按钮有 ? tooltip | ✅ | ❌ |
| 错误信息里带"查看帮助"链接 | ✅ | ❌ |
| 菜单里有"快捷键列表" | ✅ | ❌ |

## 🔄 Part 5: Skill Evolver 自动进化规则

Skill Evolver 会根据每次 UX 测试的反馈自动更新本手册：

| 触发 | 进化动作 |
|------|---------|
| 某反模式在测试中被发现 ≥ 3 次 | 升级为 P0 + 加具体代码位置 |
| 新发现的反模式 | 加入清单 + 标 P2（下次升级） |
| 一键化机会被实现并用户反馈好 | 升级为"推荐模式" |
| 某 Nielsen 原则评分长期 < 6/10 | 加具体修复模板 |
| 用户说"这个操作还能更快" | 记录并分析路径 |
