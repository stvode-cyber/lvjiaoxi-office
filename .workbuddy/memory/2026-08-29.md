  - `lcsDiff(keysA, keysB, origA, origB, eq, opts)`：DP 表 + 回溯，产出 `{type:'eq'|'del'|'add', aIdx, bIdx, aText, bText}` 操作序列（内部原语 `_lcsDiff`）。

### 修复 2：本地构建被更新源环境变量硬卡死（已解决）

- **现象**：`npm run dist:win` 9 秒即失败 —— `⨯ cannot expand pattern "${env.LVJX_UPDATE_FEED}": env LVJX_UPDATE_FEED is not defined`
- **根因**：`package.json` → `build.publish = [{provider:"generic", url:"${env.LVJX_UPDATE_FEED}"}]`。electron-builder 加载配置时展开该 pattern，环境变量未定义即**中止打包**。
- **这是设计自相矛盾**：`.github/workflows/release.yml` 明确把「未配置 LVJX_UPDATE_FEED → 桌面依赖 GitHub Releases 作为更新源」写成**受支持路径**（见 `draft:` 表达式与末尾说明），但该路径下打包根本跑不起来。
- **定位实验（trust-but-verify）**：
  1. `LVJX_UPDATE_FEED=https://example.invalid/feed electron-builder --win --dir` → **EXIT=0 通过**（证明除 URL 外整条打包链路健康）
  2. 未设变量 + `--publish never` → **EXIT=0 通过**（证明 `--publish never` 可绕开 pattern 展开，不产出更新源元数据）
- **修复**：新增 npm script `dist:local` = `electron-builder --win --publish never`。本地/CI 无更新源时也能产出完整安装包；`dist:win` 保持不变（CI 配了 feed 才会产出 `latest.yml`，语义正确）。
- **取舍**：`--publish never` 不生成 `latest.yml`，故本地包不带静默更新能力——这是**正确**的：更新元数据本就只应在真正发布到更新源时产生。
