## 桌面端应用内静默更新（更新机制修复）· 全链路交付

**背景**：用户明确「后面版本更新不需要再去下载原件，而是提示更新、完成更新动作」。
此前桌面端更新逻辑虽写了 electron-updater 集成，但有三处根因导致永远走「前往下载」手动重装：
1. `electron/feed-config.js` 的 `resolveUpdateProvider` 对非 GitHub 的 `version.json.url`（https://lujax.fun/releases）
   返回 null → 无更新源 → `_autoEnabled` 永 false；
2. `electron-updater` 依赖未装本地（try/catch 置 null）→ 主进程 IPC 实际不可用；
3. 前端 `app/js/updater.js` 在 `notify`/`applyUpdate` 前置 `_autoEnabled` 判断 → 桌面只能「前往下载」。

**交付（三处修正）**
- `electron/feed-config.js`：`resolveUpdateProvider` 新增——`versionJsonUrl` 为非 GitHub 的 http(s) 时直接返回
  `{ provider:"generic", url: normalizeFeedUrl(...) }`，使 `lujax.fun/releases` 默认启用静默通道
- `app/js/updater.js`：去掉 `_autoEnabled` 变量与前置判断；桌面端只要 `isNativeShell() && electronAPI.invoke`
  即走 `downloadAndInstall`（静默下载→安装），按钮统一「立即更新」；`downloadAndInstall` 在 `updater:download`
  回传 ok:false 时兜底打开发布页（结构与主进程 `updater:error` 兜底一致）
- 本地装 `electron-updater@^6.8.9`（devDependencies，原 `^6.3.0` 由 npm 解析到 6.8.9）→ 打包后运行时可用
- 测试：新增 `_feed_config_test.js`（10 断言，验证 generic/github/null 解析）；`_updater_fallback_test.js` DOM2
  改为「桌面走静默通道、download 失败回退打开发布页」新契约；全量 **85 套件 0 失败**
- 四端同源同步 ✅；bump **1.0.14**；重建 Windows 安装包
  `dist/绿角犀 Office Setup 1.0.14.exe`(nsis) + `绿角犀 Office 1.0.14.exe`(portable) + `latest.yml`(指向 1.0.14) + .blockmap
